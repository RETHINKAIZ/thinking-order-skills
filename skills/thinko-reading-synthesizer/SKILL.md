# 阅读综合中枢

> Thinking Order 合并版 skill：把长材料压缩成观点、洞察、结论和行动。

## 大原则

默认先产出有用结论，不把摘要、分析、洞察拆成多轮流程。

如果用户没有提供原文或材料，先要求粘贴材料；如果材料很长，先处理用户给出的片段，并说明可继续分批。

## 适用任务

- 总结文章、报告、会议记录、访谈、长对话。
- 分析作者观点、论证结构、隐含假设和可质疑点。
- 从用户反馈、复盘材料、行业报告中提炼洞察。
- 输出管理层摘要、行动项、未决问题和后续建议。

## 快速判断

| 材料类型 | 输出重点 |
|---|---|
| 文章/书摘 | 核心观点、结构、证据、启发 |
| 行业报告 | 关键趋势、机会、风险、对用户的影响 |
| 会议记录 | 决策、行动项、负责人、截止时间、未决问题 |
| 用户访谈/反馈 | 主题聚类、洞察、证据原话、产品机会 |
| 复盘材料 | 事实、原因、经验、改进动作 |

## 工作流程

1. **识别材料类型和用户目标**：总结、分析、提洞察或提行动。
2. **压缩事实**：提取关键事实、数字、人物、时间、决策。
3. **提炼结构**：区分事实、观点、证据、假设、结论、建议。
4. **输出高价值结果**：按用户目标选择摘要、洞察表、纪要或批判性分析。
5. **标注不确定性**：缺失、推测、需要核验的内容单独列出。

## 输出模板

### 通用摘要

```markdown
## 一句话结论
[结论]

## 核心要点
- [要点]

## 关键证据
- [证据/原文依据]

## 启发或行动
- [下一步]
```

### 会议/访谈/反馈

| 类型 | 内容 | 证据/来源 | 行动建议 |
|---|---|---|---|

然后补充：
- 决策和行动项
- 未决问题
- 风险或需核验内容

## 质量标准

- 不把总结写成流水账。
- 不把作者观点当成事实。
- 洞察必须有证据支撑。
- 行动项要尽量包含事项、负责人、时间；没有就写“未提及”。
- 面向管理层时优先输出结论和影响。

## 低 Token 规则

- 用户要短摘要时，不附长分析。
- 用户要洞察时，不重复全文。
- 不解释阅读方法，直接交付摘要、洞察或纪要。
