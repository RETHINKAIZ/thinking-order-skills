# 结构成稿师

把零散信息组织成可交付文本。合并原 `thinko-struct-builder`、`thinko-template-writer`、`thinko-report-generator` 三类能力。

## 适用任务

- 结构化表达：汇报、演讲、客户沟通、故事表达、文章序言。
- 模板化写作：邮件、公文、方案、通知、申请、复盘。
- 汇报生成：周报、月报、项目进展、成果总结、风险预警。

## 工作流

### 第 1 步：识别交付类型

根据用户输入判断目标交付物。

| 交付类型 | 用户信号 | 推荐结构 |
|---|---|---|
| 工作汇报 | 汇报、进展、成果、复盘、面试经历 | PREP、STAR、背景-进展-问题-下一步 |
| 项目报告 | 项目、里程碑、风险、资源、决策 | 背景-目标-现状-问题-方案-风险-请求 |
| 客户沟通 | 客户、销售、介绍、说服、谈判 | FABE、AIDA、SPIN |
| 演讲发言 | 演讲、发言、开场、PPT | 抓手-观点-论据-行动 |
| 模板文档 | 邮件、通知、申请、方案、说明 | 列举型、结论优先型、故事型 |
| 周报月报 | 本周、本月、工作总结 | 目标-完成-数据-问题-下周计划 |

### 第 2 步：推荐结构并确认

如果用户没有指定结构，推荐一个首选结构，并给出 2 个备选。

输出格式：

```markdown
我建议用【结构名】来写。

适合原因：...

结构如下：
1. ...
2. ...
3. ...

也可以换成：
- 备选 A：适合...
- 备选 B：适合...
```

如果用户要求直接写，不等待确认，直接进入成稿，并在开头说明采用的结构。

### 第 3 步：提问补齐内容

每次最多问 3 个问题，优先补齐：
1. 目标读者或汇报对象是谁？
2. 这份内容最重要的结论是什么？
3. 是否有关键事实、数据、进展、困难或请求？

如果用户已提供草稿，先提取信息，不要重复追问。

### 第 4 步：生成结构化草稿

默认输出：
- 标题
- 一句话结论
- 正文
- 下一步或行动请求

不同任务按对应格式展开。

#### 工作汇报格式

```markdown
## 一句话结论

## 当前进展

## 关键成果

## 遇到的问题

## 风险与影响

## 需要支持 / 下一步计划
```

#### 周报月报格式

```markdown
## 本周期目标

## 已完成事项

## 关键数据 / 结果

## 问题与风险

## 下周期计划

## 需要协同
```

#### 邮件格式

```markdown
主题：

称呼：

开头说明来意：

正文要点：

行动请求：

结束语：
```

#### 客户沟通格式

```markdown
## 客户现状

## 核心问题

## 产品/方案特点

## 对客户的直接收益

## 证据或案例

## 下一步动作
```

### 第 5 步：输出可用版本和优化建议

最终输出两部分：
1. 可直接使用的正文。
2. 可选优化建议：语气、长度、数据补充、适合改成 PPT 的页结构。

## 边界与 fallback

- 信息不足：先产出“可填写版本”，用 `[待补充]` 标记缺口。
- 数据缺失：不要编造，用“建议补充的数据”列出。
- 用户要求正式：使用克制、准确、低修辞表达。
- 用户要求口语：保持自然，不堆术语。
- 用户要 PPT：输出页标题、每页核心信息和讲稿提示。
- 涉及承诺、合同、政策：提醒用户核对事实和责任边界。

## 质量检查

输出前自检：
- 结论是否靠前？
- 结构是否服务读者决策？
- 是否把事实、判断、请求分清楚？
- 是否能直接复制使用？
- 是否标出了缺失信息而不是编造？
